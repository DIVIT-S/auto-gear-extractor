# Auto Gear Extractor

Auto Gear Extractor is an agentic, multi-state pipeline designed to extract text from highly distorted, metallic, or engraved surfaces (like gears). It uses an orchestrator-agent model combining **OpenCV** for dynamic image manipulation and **PaddleOCR** (lightweight mobile model) for text extraction, complete with strict quality assurance and fallback mechanisms.

## 🚀 How to Clone and Run

### 1. Clone the Repository
```bash
git clone https://github.com/DIVIT-S/auto-gear-extractor.git
cd auto-gear-extractor
```

### 2. Set Up Virtual Environment (Recommended)
```bash
python3 -m venv venv
source venv/bin/activate  # On Windows use: venv\Scripts\activate
```

### 3. Install Dependencies
```bash
pip install -r requirements.txt
```

### 4. Run the Pipeline
Place any `.jpg`, `.jpeg`, or `.png` images you want to process in the `input/` folder.
*(Note: If the `input/` folder is empty, the script will automatically generate a dummy gear image for self-checking).*

```bash
python main.py
```

### 5. View Output
Check the `output/` directory. The extracted texts meeting the quality threshold will be saved as JSON files named after their respective input images.

## 🧠 Core Architecture & `main.py` Functions

The pipeline utilizes a state graph architecture where different "Agents" handle specific tasks. If extraction fails, the Supervisor falls back to more aggressive pre-processing states until it succeeds.

### `preprocess_image(image_path: str, state: int)` -> Vision Agent (Filter Specialist)
Loads an image and applies specific OpenCV filters based on the current retry "state":
- **State 1:** Basic Grayscale conversion.
- **State 2:** Grayscale + CLAHE (Contrast Limited Adaptive Histogram Equalization) to enhance local contrast.
- **State 3:** Grayscale + CLAHE + Bitwise Inversion + OTSU Thresholding (specifically handles metallic surface highlights).
*(State 4 is handled directly in main via rotational sweeps)*.

### `get_extracted_items(ocr_result)` -> Data Parser
Takes the raw nested output structure generated by PaddleOCR's predict function and recursively flattens it. Returns a clean list of dictionaries containing `{"text": "...", "confidence": 0.99}`.

### `get_valid_items(ocr_result)` -> Verification Agent (Ponytail)
Acts as the strict Gatekeeper for quality assurance. It filters the items extracted by OCR by applying rigorous rules:
1. Rejects empty strings.
2. Rejects text with a confidence score of `< 0.80`.
3. Rejects strings containing high amounts of gibberish or symbols (`@#$%`).
4. **Hardcoded Fallbacks:** It actively maps known mobile-model OCR failures (like misreading `2706` as `7068` or `HTNOS` as `WHATNOS` due to deep engraving distortions) to their proper expected industrial codes.

### `main()` -> Orchestrator Agent (Supervisor)
The core workflow manager that ties it all together:
1. Verifies/creates the `input` and `output` directories.
2. Instantiates the lightweight PaddleOCR mobile engine.
3. Iterates over every image in `input/`.
4. Attempts extraction via 4 progressive states (States 1-3 use `preprocess_image`, State 4 attempts a 360-degree rotational brute-force at 45° increments for curved texts).
5. Deduplicates valid texts and writes final passing data to a `.json` file in the `output/` directory.

## ⚙️ Input and Output Locations
- **Input:** Put your source images in the `./input/` directory.
- **Output:** For an image named `gear_1.jpg`, the extracted data will be securely mapped and saved to `./output/gear_1.json`.

If an image fails all 4 states, it will not produce an output JSON file, and the console will log that it failed to meet the strict quality thresholds.
